What Is SAP Joule? Capabilities, Requirements and Practical Use Cases

Joule is SAP's AI copilot, embedded across SAP's cloud applications. This guide explains what it does, how agents and Joule Studio fit in, what you need to switch it on and how SAP handles your data.

By the Oddesy Consulting and Services team · 23 Nov 2026

Joule is SAP's AI copilot. It is a natural language assistant built into SAP's cloud applications, such as SAP S/4HANA Cloud, SAP SuccessFactors and SAP Ariba. Unlike a general-purpose chatbot, Joule is grounded in your SAP business data and processes, and it only shows users the data their existing authorisations allow. You can ask it a question, ask it to open the right app, or ask it to do a task such as creating a purchase requisition. With Joule Agents and Joule Studio, SAP has extended it from answering questions to running multi-step work.

What Joule can do: the four interaction patterns

SAP's own training material groups Joule's capabilities into four patterns (SAP Learning):

PatternUser intentExample request
InformationalTo know something"What is the status of purchase order 4500018543?"
NavigationalTo go somewhere"Show me all open production orders", with a link to the right Fiori app
TransactionalTo do something"Create a purchase requisition for 25 office chairs from our preferred supplier"
AnalyticalTo understand something"Compare sales in Germany and France this quarter"

Beyond these, Joule can summarise information and draft content such as emails or job descriptions from templates. Informational answers can also draw on your own documents if you set up document grounding, which lets you upload company documents to the Joule service.

What Joule can actually do in your system depends on which SAP products you integrate and which capabilities SAP has delivered for them. Check the scope for each product rather than assuming every example works everywhere.

The Joule family: agents, developers, consultants and Joule Work

Joule Agents

SAP describes Joule Agents as AI-powered automation workflows. They interpret a request in natural language, plan a series of steps and carry them out across SAP systems such as SAP Cloud ERP, SAP SuccessFactors, SAP Concur and SAP Fieldglass. The difference from the basic assistant is that an agent pursues a goal across several steps, rather than answering one prompt at a time.

Joule for Developers and Joule for Consultants

  • Joule for Developers helps developers in SAP Build Code and the ABAP Development Tools for Eclipse, for example by generating code, explaining code or generating a CDS view.
  • Joule for Consultants is a separate offering aimed at SAP consultants and project teams.

Joule Work and Joule Studio

At SAP Sapphire in May 2026, SAP introduced Joule Work, a workspace that brings apps, agents and workflows into one place, and the new Joule Studio. According to SAP's announcement, Joule Studio is a fully managed offering to build and run AI agents, applications and workflows:

  • Intent-based development: describe the goal in natural language, and Joule Studio generates requirements, specifications, code scaffolding, tests and a working preview.
  • Open tooling: developers can continue in tools such as Visual Studio Code or Cursor, use frameworks such as LangChain, Pydantic AI and LlamaIndex, and orchestrate agents visually with an embedded n8n environment.
  • Managed runtime: agents run in a managed, sandboxed environment with built-in observability, and get long-term memory backed by SAP HANA Cloud.

SAP also notes that Joule Studio is the next generation of SAP Build. If you build extensions today, expect your tooling to move in this direction.

What you need to use Joule

SAP's Joule integration guide sets out the prerequisites. In summary:

Commercial

  • A valid licence for an SAP product that supports Joule integration, such as SAP SuccessFactors or SAP S/4HANA Cloud Private Edition, running in a supported data centre.
  • Joule Base or AI units (SKU 8019164). Which capabilities each covers is a commercial question for your SAP account executive.

Technical

  • An SAP BTP enterprise global account, because Joule runs on SAP BTP services.
  • SAP Cloud Identity Services: Identity Authentication for login and Identity Provisioning for users and authorisations. Joule and all integrated products must use the same Identity Services tenant, with users identified consistently by a global user ID.
  • SAP Build Work Zone, which Joule uses to navigate to applications and handle role-based access. Conversational search does not require it.
  • The Joule entitlement in your global account, followed by running the Joule booster to set up the integration.

Customer-managed or SAP-managed?

There are two ways to provision Joule. With customer-managed provisioning, your team configures SAP BTP subaccounts, entitlements, trust and integrations step by step. With SAP-managed provisioning, SAP handles the technical set-up and you manage product selections in SAP for Me. SAP recommends the SAP-managed route, and it is required for Joule Work.

Example: S/4HANA Cloud Private Edition

For Private Edition, the integration guide lists steps including: integrating the system with Identity Authentication, creating an SAP Build Work Zone instance, setting the system up as a content provider through SAP Cloud Connector, running the Joule booster, configuring destinations and Identity Provisioning, and activating the Joule plug-in in the SAP Fiori launchpad. SAP warns that paths exposed through Cloud Connector for this purpose are reachable via the public internet, so only expose what is needed. If you are still choosing an edition, our comparison of S/4HANA Cloud Public and Private Edition may help.

Joule is designed around SAP's cloud products. If you run S/4HANA on premise, confirm with SAP which Joule capabilities, if any, are available for your system before you plan around them.

Testing updates before they reach production

SAP is introducing a Joule Preview Landscape so customers can validate updates before they reach production. According to the integration guide, it is available in the EU10 and EU30 data centres, with framework releases staying in preview for two weeks and content releases for four weeks before moving to production.

How SAP handles your data

Data handling is usually the first question from security and works council teams. SAP's Responsible AI page states:

  • SAP does not share customer data with third-party LLM providers to train or improve their models.
  • When an SAP AI feature uses a third-party hosted foundation model, the data is sent to the provider for processing only, and is not stored or retained by the provider.
  • Where the contract permits, SAP may use customer data to improve existing AI features of the subscribed cloud service and, under the product development schedule, to develop new ones. Customers can see where their data may be used and opt out in SAP for Me.
  • SAP user interfaces show a notice when a user triggers an AI feature or sees AI-generated results.

Joule also respects the roles and authorisations users already have. Clean authorisations matter more, not less, once users can ask for data in plain language.

Practical use cases to start with

  • Casual users: employees who only occasionally use SAP can find the right app or check a status without training on transaction codes.
  • Procurement and finance: checking purchase order and invoice status, drafting requisitions, and summarising open items.
  • HR tasks in SAP SuccessFactors, one of the products Joule integrates with.
  • Documentation questions, using document grounding with your own process guides.
  • Development: generating and explaining ABAP or CAP code to speed up extension work.

How to get started

  1. Check eligibility. Confirm which of your SAP cloud products support Joule, in which regions, and what your contract includes.
  2. Choose provisioning. SAP-managed is simpler and required for Joule Work; customer-managed gives full control over the BTP set-up.
  3. Fix identity first. A single Cloud Identity Services tenant and consistent global user IDs avoid most integration problems.
  4. Review authorisations and data quality. Joule can only give good answers from good data and correct roles.
  5. Pilot with one group and a handful of scenarios, measure the effect, then expand.
  6. Plan for agents and extensions on SAP's platform, in line with clean core principles. Our article on SAP clean core explains why that matters.

Key takeaways

  • Joule is SAP's AI copilot, embedded in SAP's cloud applications and grounded in your business data and permissions.
  • It answers, navigates, executes and analyses; Joule Agents add multi-step automation, and Joule Studio is SAP's managed environment for building agents.
  • You need a supported SAP cloud product, Joule Base or AI units, SAP BTP, and Cloud Identity Services; SAP-managed provisioning simplifies the set-up.
  • SAP does not share customer data with third-party LLM providers for training; review the contract terms on SAP's own use of data.

Frequently asked questions

What is SAP Joule?

Joule is SAP's generative AI copilot: a natural language assistant embedded across SAP's cloud applications. It is grounded in your SAP business data and processes, and respects each user's existing roles and authorisations.

What can Joule do?

SAP groups Joule's interactions into four patterns: informational (answer a question), navigational (take you to the right app), transactional (carry out a task such as creating a purchase requisition) and analytical (summarise and compare data). Joule Agents extend this to multi-step tasks across SAP systems.

What do I need to use Joule?

A licence for an SAP cloud product that supports Joule in a supported region, Joule Base or AI units, and the technical set-up: an SAP BTP enterprise account, SAP Cloud Identity Services and the relevant entitlements. SAP-managed provisioning reduces the technical work.

Does SAP use my data to train AI models?

SAP states that it does not share customer data with third-party large language model providers to train their models, and that third-party model providers process the data without storing it. Where the contract permits, SAP may use customer data to improve its own products, and customers can review and opt out in SAP for Me.
